# 采购文字批量导入

本功能在已有“手动采购与库存”上追加文字解析与核对，复用现有采购事务、家庭 RLS 和幂等请求编号。不调用 AI，不上传或识别小票图片。

## 如何使用

打开「采购 → 记一笔采购」，在「粘贴小票文字」输入多行内容：

```text
鸡蛋 | 12 | 个 | 4.99
牛肉 | 0.68 | kg | 11.49
番茄 | 4 | 个 | 2.99
牛奶 | 1.5 | L |
```

每行必须有四列，以 `|` 或全角 `｜` 分隔：**食材名称 | 数量 | 单位 | 商品行总价**。金额默认 USD，为整行总价而非单价。未知价格仍需保留最后一个竖线、将第四列留空；0 表示真实免费。可接受 `$4.99` 或 `USD 4.99`。不接受千位逗号、指数记数、分数、负数或需要四舍五入的金额。

1. 点击「解析并检查」。看到每行的原始行号、匹配结果及换算后的数量。任何错误都会显示行号并阻止整批转入核对单；不静默跳过商品。
2. 修正错误后重新解析。全部有效时，点击「将 N 项加入核对单」。此时**尚未入库**，不会写数据库。
3. 在下方「采购核对单」填写整单共用的采购日期、商店和备注。核对每行数量、基础单位、价格、到期日和存放位置。未匹配食材可编辑名称与分类；已匹配食材沿用原目录名称/分类/基础单位，可通过食材下拉框改为另一项或新建。
4. 勾选需要入库的商品；未勾选的商品不提交，不能把未选择行的缺失值当成入库错误。全部取消勾选时确认按钮不可用。
5. 点击「确认整单入库」。只提交勾选项，全部写入同一采购事务；任何一项无效整单回滚。可查看采购单、批次和流水。
6. 成功后如果还有未勾选商品，可点「继续处理未勾选商品」，仅把剩余项放进新的采购请求；不会重复提交已入库项。

整张小票共用采购日期；不同采购日期目前请分成不同采购单。每行保质期可分别填写，未知到期日留空，不会自动猜测。

## 单位与匹配规则

- 重量：g/克/公克/gram/grams；kg/千克/公斤/kilogram/kilograms 精确乘 1000 转为 g。
- 体积：ml/毫升及 milliliter/millilitre 的单复数；L/升/liter/litre 的单复数精确乘 1000 转为 ml。
- 计数：个/只/枚/pc/pcs/piece/pieces/each/ea → 个；pack/packet → 包；bag → 袋；bottle → 瓶；box/carton → 盒；serving/portion → 份，均支持英文复数。
- 不支持 oz/lb 等需要额外换算规则的单位；请先使用确定的基础单位输入。不会把“个”换算成“g”。
- 使用 BigInt 整数缩放，避免二进制浮点误差。基础数量最多三位有效小数，金额最多两位有效小数；精度不足会报错，不会擅自舍入。比如 0.68kg → 680g，0.000001kg → 0.001g。
- 名称按 Unicode 规范化、大小写不敏感、首尾及重复空格规范化后，精确匹配已有中文名称或已有英文别名（name_en）。不自动翻译，不做近似猜测。
- 名称匹配多个食材会报错；匹配食材单位不兼容也会报错。请修正原文名称/单位，不会悄悄创建重复且单位冲突的食材。
- 未匹配食材标注“待新建”，分类默认“其他”，由用户核对调整后才创建。多个同名有效行保留为独立批次，不擅自合并小票商品。

每次解析最多 50 个非空商品行，最多 20,000 字符；核对单包含原有商品在内也最多 50 项。空白行明确计数，不作为商品，错误行号保留原始位置。表格标题、代码围栏和说明文字不会被默默忽略，请仅粘贴标准商品行。

## 草稿、重试与数据安全

导入会替换唯一的初始空白商品行，其余情况都追加到现有未提交核对单，保留已有采购日期、商店、备注和商品。重复点击“加入核对单”不会重复追加同一次解析；修改原文后可重新解析并追加。

核对结果、勾选状态、原始行号和原请求编号随采购草稿一起保存在本标签页 sessionStorage，刷新后保留。**尚未加入核对单的粘贴区原文不暂存**，刷新可能丢失原文。草稿按家庭/用户隔离，浏览器存储失败时不会显示已导入。

只把选中商品组成已有 `record_purchase` 的 payload，仍经过服务端校验和数据库权限/事务约束。不会信任前端声明的家庭或角色。未选中商品仅留在浏览器草稿，不写进采购、库存或流水。提交中禁用核对和解析区，避免结果不确定时改动同一个请求内容。

网络结果不确定时应保留原草稿重试，不要清除存储或另建同样的采购。主动改成新的请求编号、换设备重复创建同一张小票，不属于相同幂等请求。数据刷新共享，Realtime 仍未实现。

## 发布与验收

本轮**无需新增或重跑 SQL**。依赖前一轮已经执行的 `202610260002_inventory.sql`。通过 PR 合并本分支到 main，等待 CI 与 Vercel 部署；保持现有 Supabase 环境变量。

自动化覆盖解析边界、逐行错误、匹配/单位冲突、UI 核对选择与重复点击、草稿恢复及解析结果进入真实 PostgreSQL 引擎采购事务。Playwright 的现有导航基线不等于托管登录后的导入验收。

正式站点手动验收：

1. 登录已有家庭账号，粘贴标准多行示例，检查已有食材被正确匹配。
2. 在其中一行填负数，确认显示正确行号且不能转入任何商品；修正后重新解析。
3. 转入核对单，检查 0.68kg 显示为 680g、价格仍为整行 11.49、未知到期日为空。
4. 修改一行数量/分类/存放位置，取消勾选另一行，填写采购日期并确认。
5. 核对采购明细、库存总量和批次，只能出现选中项；刷新不重复入库。另一名成员刷新看到同一结果。
6. 试用“继续处理未勾选商品”，确认新请求只包含剩余商品。

本轮不修改已暂存的邮箱模板，不实现共享购物清单、再次购买、菜谱或烹饪扣减。
